# Motion 模板创建与校正工作室｜完整启动 Prompt

可直接调用已安装的 `$motion-template-studio`；使用插件时，先选择“Motion 模板创建与校正工作室”，再发送同一份Prompt。两者选择一个入口即可。

以下默认执行前期“目标视频→新的.motion模板”。已有模板检查时，只更改任务模式。

```text
使用 $motion-template-studio（Motion 模板创建与校正工作室）。

【一、任务配置】
任务模式：{{视频转模板 / 检查与校正；默认视频转模板}}
输入资料：本轮上传的目标视频、.motion文件及补充素材；以实际可读取附件为准。
现成参考模板：{{可选；未提供则从资料库选择适用代码结构}}
重点效果与保留范围：{{默认覆盖全片的构图、镜头、动作、转场、动态字幕及声音编排}}
画幅与时长：{{默认按目标视频识别，并注明模板可调整的范围}}
输出目录：{{AUTO：在独立任务目录制作，保留原素材与原模板}}
资料仓库：https://github.com/wakazhangjiahuang/motion-template-studio
资料分支：main；开始时记录实际使用的提交版本。

【二、目标与边界】
本轮完成前期模板创建：目标视频→观察证据→代码重建→参数通用化→真实验证→完整作者.motion。
由你完成中间工程，不要求我先提供已制作好的工程；MP4用于预览验收，主交付是新的可复用.motion。
后期数字人口播、素材混剪制作新成片，本轮只保留兼容接口，不展开执行。

【三、执行流程】
1. 核对实际附件、仓库访问、本地MCP和运行工具。优先使用已连接MCP或本地仓库；否则通过已授权GitHub连接读取相关资料。连接不可用时明确说明，并使用可用的随附资料，不虚构调用记录。
2. 识别完整视频的时基与展示结构，连续审看，提取关键动作前后相邻帧。区分事实、实现推断与未知；建立“原片时间→展示模块→实现代码→验收证据”的对应关系。
3. 根据观察检索镜头/动画配方、真实源码和校验案例。先核对引擎、接口、许可与验证状态；优先复用稳定目录、组件接口和参数合同，再针对参考修改实现与时间轴。
4. 实现可编辑动画、素材槽和字幕机制，覆盖片尾与过渡。提炼实际被代码消费的文字、颜色、字体、布局、素材和节奏参数，写清容量、时长及缺素材策略；超容使用分段、分页或清晰反馈，保持内容完整可读。
5. 实际渲染，核对画面、运动和声音；修正问题后复测。至少完成参考对照、新内容替换、边界输入、完整解码，以及干净目录解包后重新导出。逐项记录PASS / FAIL / NOT_RUN / BLOCKED及真实证据。
6. 按MotionGit作者内容规范和已验证官方工具生成完整.motion，检查源码、引用、参数、资源、依赖声明、许可及完整性。正式完成须以本次模板的实际验收为准。

【四、检查与校正模式】
若输入是已有.motion，先识别作者包或个人分发封套，再按相应入口处理。
作者包先只读检查；可自动修正的目录/完整性问题使用源哈希绑定计划，另存新包并复审。代码、参数、素材或视觉问题在工作副本中修改、重打包并复测。
保留原件；不读取或传播个人Key，不重包受保护核心，也不把重算摘要当成来源真实性认证。

【五、交付要求】
A. 完整、可复用的作者.motion文件。
B. 使用说明：适用效果、支持宿主与依赖、需要的素材、参数/容量、运行和导出步骤、限制；说明如何交给Codex或WorkBuddy等具备相应执行能力的客户端使用。
C. 本次真实预览、参考对照与验证报告，列出已通过、失败和待验证项。
D. 如有修正，附问题、改动和复测记录。

能执行的直接推进到成果。缺少目标视频或必要材料时，仅询问影响执行的关键缺项；已有独立工作继续完成。运行受阻时保留明确标注的待验候选与复测命令，不把诊断骨架或未验成果标为正式完成。
```

MCP当前提供本地stdio实现；仓库存在不表示托管插件已自动连接本机文件或云端MCP服务。按实际客户端能力配置，不需要重复启动两套制作流程。
