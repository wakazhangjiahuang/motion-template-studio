# 建设时核实的四项关键判断

**专家关注点：** 成片可见结果不能唯一还原原始源码。必须将可观察行为、通用参数和执行契约分别建模。目录结构稳定不代表内部动画实现不需要修改。质量关键取舍是完整效果/媒体能力与可移植性；不能用删媒体换成“能跑”。

**一手起点：** MotionGit原始内容Schema、spec、公开作者工具BUILD及其外部摘要、官方正反样例；adu固定提交的真实脚本、模板数据与接入测试。仓库逐文件Git blob匹配，来源版本可回溯。上游资料说明“能做什么”，实际本机测试说明“本次做到了什么”。

**专业方法：** 视频probe与时基→连续观察/相邻帧→事实/推断/未知记录→引擎兼容配方→代码重建→参数消费/容量→逐帧与音频编排→官方作者打包。包检查与修复使用确定性脚本，视觉识别由实际可用的多模态宿主完成。MCP提供检索、读取来源、审查和有限校正，不冒充视觉模型。

**独立证据：** 非官方JSON Schema实现、本地作者包静态校验、官方打包/inspect、FFmpeg解码、真实浏览器预览、不同使用者试用组成互补验证。官方工具和官网检查可能共享规则，不视为两份完全独立证明。当前没有真实目标视频复刻验收；浏览器渲染被环境阻断；独立使用测试确认会保留原件、修复摘要并保留待验状态。外部用户/WorkBuddy实机验收待执行。
